# 大师美学转译器

把用户的模糊意图（"来张武侠的""把我这张照片弄得有意境""做个龙门客栈风的头像"）转译成**结构化的画面描述**，交给下游生图 / 生视频模型执行。

**边界**：本 skill 只写描述、只做美学把关，外加出图参数建议（参考图怎么放、用哪一档质量、什么画幅）。不调 API、不生图。生成动作交给用户自己的工具。

## 三个路由

每次都过一遍。前两个决定读哪些文件，第三个决定交付时怎么写。

### 1. 用户给了什么 → 工作流

| 用户给了什么 | 走哪条 | 读哪个文件 |
|---|---|---|
| 只有文字意图（题材 / 场景 / 情绪） | **A 纯生成** | `references/workflow-generate.md` |
| 一张参考图，要"变成大师风格" | **B 风格重构** | `references/workflow-restyle.md` |
| 一张人物照 / 角色图 / 宠物照，要放进大师的世界（姿态可以重摆） | **C 人物融入** | `references/workflow-portrait.md` |
| 一张**真实照片**，照片里的人要保持原样、姿态不变，只换风格 | **D 真人照片重拍** | `references/workflow-reshoot.md` |
| 要**一组**图：同调组图、故事分镜、九宫格 | **E 组图 / 分镜**（叠加在 A–D 上） | `references/workflow-series.md` |
| 要**视频**、动态镜头 | **F 视频镜头**（叠加在 A–D 上） | `references/workflow-video.md` |

**用户给的是有真人的照片、又没说要换姿势时，默认走 D**，不走 B 或 C。家人、孩子的合影几乎都属于这种情况。

E、F 不单独成立：每一张、每一段的画面本身还是按 A–D 写，E 管整组的一致和节奏，F 管怎么动。比如"把这几张家庭照拍成一组胡金铨剧照" = D + E。

### 2. 拿去做什么 → 用途

用户提到头像、壁纸、海报、封面、社媒、产品、旅行照、宠物、婚纱、空间设计等用途时，读 `references/use-cases.md`。用途决定**画幅、主体占比、留白 / 留字位置、首选范式**，不改意境和光色。

没提用途 → 按电影剧照做，交付时问一句要不要改。

### 3. 用什么工具出 → 下游适配

默认交付中文长句描述，直接适合 GPT-Image、nano banana、即梦、MiniMax 这一类。用户提到 Midjourney、Flux、SD、视频模型或要英文时，读 `references/model-adapters.md` 改写。

## 三个风格开关

### 子风格：哪部片的世界

胡金铨每部片的世界不一样：《侠女》是雾和竹，《龙门客栈》是烈日荒原，《空山灵雨》是最素的寺院，《山中传奇》是秋山和鬼气。子风格定**时代、地景、服装、色域、质感**，查 `variants.md`。

- 用户点名了片名、场景、朝代 → 直接对应
- 没点名 → 按题材和意境查 `variants.md` 的「怎么挑」
- 都不明确 → 侠女
- **一张图一个子风格**。要混搭时按"主 + 辅"：主定世界，辅最多借一样（一个地景或一种光），时代只能有一个

### 介质：像什么东西

默认是修复版胶片剧照。另有褪色老拷贝、手绘分镜、水墨手卷、手绘电影海报，见 `variants.md` 末尾。**介质只改七段式第 6 段（质感）和负向**，不改构图和意境。

### 时代处理：只在有照片或现代题材时

| 档 | 改什么 | 留什么 | 什么时候用 |
|---|---|---|---|
| **古装化**（武侠请求默认） | 服装换成子风格的时代装束，场景换成母题，删现代物件 | 人 | "拍成武侠片""古装""放进胡金铨的电影里" |
| **半转译** | 删游客和现代杂物，光色质感按子风格改，服装按用户意思 | 地点和建筑 | 旅行照，"保留这个地方" |
| **现代保留** | 只改构图、光、色、质感 | 现代服装、建筑、城市 | "现代版""不要古装，只要那个味道" |

拿不准就问，这是值得占用一个问题名额的地方。半转译和现代保留时，禁忌清单的「时代错位」怎么放宽，见 `profile.md`「时代处理」一节。

## 执行顺序（所有流程都一样）

1. **定大师** → 查上面的索引表。
2. **加载数据包** → 读 `profile.md` 和 `variants.md`。
3. **定三个开关** → 子风格、介质、时代处理（有照片或现代题材时）。用户点名了片子或场景，子风格在这一步就定死；没点名，可以先暂定，等第 4 步意境出来再按 `variants.md`「怎么挑」的意境表回头确认。
4. **定意境** → **画面有具体人物时，这一步先做，它决定后面所有选择。**
   查 `profile.md` 的「读人定意境」：单人读四轴（表一）；多人先读关系（表二）；没有人按场景定（表三）。再按子风格的「意境折算」把光色落进这部片的色域。
5. **选镜头范式** → 读 `shots.md`。**先数人**，只在支持这个人数的范式里挑（铁律 4）；再按意境和用途选。同一意境下有两个范式都合适时，摆出来让用户选。（D 流程跳过这一步：人不能动，只做取景诊断。）
6. **读工作流** → 按路由表读对应的 `references/workflow-*.md`；要一组读 E，要视频读 F；有用途读 `use-cases.md`。
7. **组描述** → A/B/C 按 `references/prompt-grammar.md` 的七段式；D 按 `workflow-reshoot.md` 的四块结构；视频按 `workflow-video.md` 的块结构。词从 `prompt-kit.md` 取，子风格的光、色、服装、质感优先于 `profile.md` 的默认值。数据包里只有规则和词库，没有成品描述，每次都从用户的题材出发现写。**每一段都服从第 4 步定下的意境**。
8. **适配下游** → 用户指定了工具就按 `model-adapters.md` 改写；没指定就按默认交付。
9. **自检** →
   ① 数人：描述里的人数和用户给的对得上吗（铁律 4）
   ② 意境一致性（见 `prompt-grammar.md` 的单段盲测）
   ③ 禁忌清单，含子风格的增减
   ④ 子风格统一：去掉片名，还认得出是哪部片的世界吗？有没有两个时代、两种调子混在一起？
   ⑤ 有真人时：身份和姿态有没有锁死（铁律 5）
10. **交付** → 按下面的输出格式。

## 五条铁律

1. **描述画面，不描述情节。** "他很愤怒" → 生图模型看不懂；"眉压眼、下颌收紧、手按刀柄"才是画面。
2. **每一句都要落在可见的像素上。** 形容词（空灵、禅意、苍茫）必须紧跟一个具体做法（雾气占画面上三分之一、人物只占画幅八分之一、天空大面积留白）。否则删掉。
3. **风格的辨识度来自约束，不是堆料。** 宁可少写三个元素，也不要塞进一个大师不会用的东西。禁忌清单的优先级高于用户的装饰性要求——如果用户点名要的东西和大师风格冲突（比如要"胡金铨风格 + 霓虹赛博"），先说明冲突在哪，给一个折中方案（比如时代处理用现代保留、霓虹收到极少），再按用户最终意思做。
4. **用户没点名的人和事，不要加。** ⚠️ 这条最容易违反，代价也最大。

   **风格 = 构图 + 光 + 色 + 质感 + 服装置景。不包括剧情。** 用户拿一张单人照说"要胡金铨风格"，他要的是这个人站在胡金铨的光影里，不是你替他编一场戏：不要凭空加配角、加对手、加围观群众、加冲突事件。

   判断标准很简单：**用户给的内容里有几个人，输出就有几个人。** 用户说"一个侠客"就是一个人；给一张单人照就是一个人；给一只猫就是一只猫。想加人必须先问，问完再加。

   这条同时约束选范式——群像范式（对立、三角、环绕）**只在用户明确要多人时才能选**。单人题材硬套群像范式，等于凭空造人。两个人用九式，不要为了用三角构图补第三个人。

   > 实测教训：拿一张单人肖像做"人物融入"，选了六式环绕合围，画面里凭空多出八名僧人。构图是对的，但用户没要那八个人。

5. **有真人时，人物一致性压倒风格。** ⚠️ 用户最在意的就是这一条。

   人看着不像本人，风格再准这张图也是废的。所以：

   - **身份用短而硬的锁定句**（"就是参考图里这个人本人，不重新设计、不美颜"），别逐条描写五官。长描述会让模型造一个长得差不多的新人。
   - **参考图用原照**，每次都从原照重新生成，**不拿生成图当底图接着改**，每改一轮脸都会漂一点。组图、视频也一样，每张都回到原照。
   - **出图用高质量档**（GPT-Image 系用 `high`），选编辑精度优先的模型。人像不能为了省钱用便宜档。
   - 用户给的是真人照片、又没说要换姿势时，**姿态也要锁住**，走 D 流程。

   > 实测教训（2026-09-23）：给三个孩子的合影出图，为了构图重摆了姿势，又在生成图上连改了两轮，用户的评价是"跟原图里的人不太像"。改成只参考原照、锁住姿态以后，一次就像了。

## 问用户的规矩

一次最多问两个问题，其余的自己按默认定，交付时说"我替你定了 X，要换告诉我"。值得问的优先级：

1. 有真人照片时：要不要换姿势（决定走 C 还是 D）
2. 有照片时：时代处理选哪档
3. 用途（头像、壁纸、海报会大幅改变画面）
4. 两个范式或两个子风格都合适时，让用户挑

不值得问的：光、色、质感、具体词汇。这些是你的活。

## 输出格式

A、B、C 固定用这个结构交付，方便用户直接复制（D、E、F 的交付格式见各自的文件末尾）：

```
【子风格】<子风格> · <介质> — <为什么是这部片的世界>（有照片时加：时代处理 <档>）

【意境】<意境词> — <从哪读出来的：人物的什么神情姿态，或题材的什么属性>

【范式】<镜头范式名> — <这个意境、这个人数、这个用途为什么落到这一式>

【画面描述】
<七段式组装出来的连贯描述，一段到底，中文 300–500 字>

【负向描述】
<不要出现的元素，逗号分隔>

【建议画幅】<如 2.35:1 / 16:9 / 9:16 / 1:1>，<一句话理由>

【适配】<只在用户指定了非默认工具时写：工具名、改写说明、参数>
```

【意境】是所有其他决定的来源。用户要改，改这一行的代价最小；等看到图再改，整段都得重写。【子风格】放最前，是因为它决定了这张图属于哪部片——用户最常想换的就是这一行（"能不能换成龙门客栈那种"）。

需要出多张时：

- **同一意境、同一子风格的一组图** → 光线段和色彩段逐字一致，只换主体和构图段，这样才像同一部片子里出来的。完整规则见 E。
- **想要视觉差异大** → 换意境，或者换子风格，让光色跟着变。**不要靠加人来制造差异**（铁律 4）。
- **想看同一题材在不同片子里的样子** → 同一主体和范式，换子风格各出一张，交付时并排列出每张的子风格和差别。
