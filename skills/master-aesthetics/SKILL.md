# 大师美学转译器

把用户的模糊意图（"来张武侠的""把我这张照片弄得有意境"）转译成**一段结构化的中文画面描述**，交给下游生图模型执行。

**边界**：本 skill 只写描述、只做美学把关，外加一条出图参数建议（参考图怎么放、用哪一档质量）。不调 API、不生图。生成动作交给用户自己的生图工具（apimart-image-gen / baoyu-image-gen / MiniMax / 即梦 / nano banana 等）。

## 工作流路由

先判断用户手里有什么，再决定走哪条：

| 用户给了什么 | 走哪条 | 读哪个文件 |
|---|---|---|
| 只有文字意图（题材/场景/情绪） | **A 纯生成** | `references/workflow-generate.md` |
| 一张参考图，要"变成大师风格" | **B 风格重构** | `references/workflow-restyle.md` |
| 一张人物照/角色图，要放进大师的世界（姿态可以重摆） | **C 人物融入** | `references/workflow-portrait.md` |
| 一张**真实照片**，照片里的人要保持原样、姿态不变，只换风格 | **D 真人照片重拍** | `references/workflow-reshoot.md` |

**用户给的是有真人的照片、又没说要换姿势时，默认走 D**，不走 B 或 C。家人、孩子的合影几乎都属于这种情况。

四条流程共用同一份大师数据包，区别在**前置分析**和**约束强度**。A、B、C 用七段式写一段完整描述；D 是编辑任务，用四块结构（锁定 / 允许 / 取景 / 光色），见 `workflow-reshoot.md`。

## 执行顺序（四条流程都一样）

1. **定大师** → 查上面的索引表。
2. **加载数据包** → 读 `masters/<代号>/profile.md`（风格档案）。
3. **定意境** → **画面有具体人物时，这一步先做，它决定后面所有选择。**
   读人物的表情、姿态、气场，查 `profile.md` 的「读人定意境」路由表，定出一个意境词。
   没有具体人物（纯风景、纯场景）时，从题材和用户的情绪词直接定。
4. **选镜头范式** → 读 `masters/<代号>/shots.md`。**范式由意境推出，不是挑好看的**。（D 流程跳过这一步：人不能动，只做取景诊断。）
   **先数人**：用户给的内容里有几个人，就只能在支持这个人数的范式里挑（见铁律 4）。
   同一意境下有两个范式都合适时，摆出来让用户选。
5. **读工作流** → 按路由表读对应的 `references/workflow-*.md`。
6. **组描述** → A/B/C 按 `references/prompt-grammar.md` 的七段式组装，D 按 `workflow-reshoot.md` 的四块结构；词汇从 `masters/<代号>/prompt-kit.md` 的词库里取。**七段全部服从第 3 步定下的意境**，不能有一段跑偏。
7. **自检** → 三件事：① 数人，描述里的人数和用户给的对得上吗（铁律 4）；② 过意境一致性检查（见 `prompt-grammar.md`）；③ 过 `profile.md` 的禁忌清单。有真人时再加一项：④ 身份和姿态有没有锁死（铁律 5）。
8. **交付** → 输出正式描述 + 负向描述 + 建议宽高比 + 一句话说明**定了什么意境、为什么是这个意境、范式怎么跟着来的**。有真人时附上出图参数建议（见铁律 5）。

## 五条铁律

1. **描述画面，不描述情节。** "他很愤怒" → 生图模型看不懂；"眉压眼、下颌收紧、手按刀柄"才是画面。
2. **每一句都要落在可见的像素上。** 形容词（空灵、禅意、苍茫）必须紧跟一个具体做法（雾气占画面上三分之一、人物只占画幅八分之一、天空大面积留白）。否则删掉。
3. **风格的辨识度来自约束，不是堆料。** 宁可少写三个元素，也不要塞进一个大师不会用的东西。禁忌清单的优先级高于用户的装饰性要求——如果用户点名要的东西和大师风格冲突（比如要"胡金铨风格 + 霓虹赛博"），先说明冲突在哪，给一个折中方案，再按用户最终意思做。
4. **用户没点名的人和事，不要加。** ⚠️ 这条最容易违反，代价也最大。

   **风格 = 构图 + 光 + 色 + 质感 + 服装置景。不包括剧情。** 用户拿一张单人照说"要胡金铨风格"，他要的是这个人站在胡金铨的光影里，不是你替他编一场戏：不要凭空加配角、加对手、加围观群众、加冲突事件。

   判断标准很简单：**用户给的内容里有几个人，输出就有几个人。** 用户说"一个侠客"就是一个人；给一张单人照就是一个人。想加人必须先问，问完再加。

   这条同时约束选范式——群像范式（对立、三角、环绕）**只在用户明确要多人时才能选**。单人题材硬套群像范式，等于凭空造人。

   > 实测教训：拿一张单人肖像做"人物融入"，选了六式环绕合围，画面里凭空多出八名僧人。构图是对的，但用户没要那八个人。

5. **有真人时，人物一致性压倒风格。** ⚠️ 用户最在意的就是这一条。

   人看着不像本人，风格再准这张图也是废的。所以：

   - **身份用短而硬的锁定句**（"就是参考图里这个人本人，不重新设计、不美颜"），别逐条描写五官。长描述会让模型造一个长得差不多的新人。
   - **参考图用原照**，每次都从原照重新生成，**不拿生成图当底图接着改**，每改一轮脸都会漂一点。
   - **出图用高质量档**（GPT-Image 系用 `high`），选编辑精度优先的模型。人像不能为了省钱用便宜档。
   - 用户给的是真人照片、又没说要换姿势时，**姿态也要锁住**，走 D 流程。

   > 实测教训（2026-09-23）：给三个孩子的合影出图，为了构图重摆了姿势，又在生成图上连改了两轮，用户的评价是"跟原图里的人不太像"。改成只参考原照、锁住姿态以后，一次就像了。

## 输出格式

A、B、C 固定用这个结构交付，方便用户直接复制（D 的交付格式见 `workflow-reshoot.md` 末尾）：

```
【意境】<意境词> — <从哪读出来的：人物的什么神情姿态，或题材的什么属性>

【范式】<镜头范式名> — <这个意境为什么落到这一式>

【画面描述】
<七段式组装出来的连贯中文描述，一段到底，300–500 字>

【负向描述】
<不要出现的元素，逗号分隔>

【建议画幅】<如 2.35:1 / 16:9 / 4:3>，<一句话理由>
```

【意境】放在最前面，因为它是所有其他决定的来源。用户要改，改这一行的代价最小；等看到图再改，整段都得重写。

需要出多张时：

- **同一意境的一组图** → 光线段和色彩段逐字一致，只换主体和构图段，这样才像同一部片子里出来的。
- **想要视觉差异大** → 换意境，让光色跟着变。**不要靠加人来制造差异**（铁律 4）。
